= Ubuntu 26.04 Offline Autoinstall for Lenovo Yoga Book YB1-X91L
:toc: left
:toclevels: 3

Build a verified hybrid Ubuntu 26.04 Desktop autoinstall ISO for the Lenovo Yoga Book YB1-X91L. The image contains the Yoga Book kernel, hardware-support packages, and their Ubuntu dependency closure, so the target machine does not need a network connection during installation.

This repository produces a *candidate image*. It is not recovery-ready until the mandatory physical-device procedure and acceptance record have passed on a YB1-X91L.

== Read this before building

WARNING: The production image dynamically discovers and erases the complete internal `CJNB4R` eMMC after its safety checks pass. It has no preservation, dual-boot, or in-place-upgrade mode. Back up all required data and prove that the backup is readable before booting the installer.

The production installer refuses to configure storage unless all of these checks pass:

* the DMI product name is exactly `Lenovo YB1-X91L`;
* exactly one non-removable MMC disk has model `CJNB4R`;
* that disk exposes matching `boot0` and `boot1` devices, distinguishing it from the `ED4QT` microSD;
* `mokutil` explicitly reports that Secure Boot is disabled.

Secure Boot must remain disabled because `7.2.0-yogabook-20260828-163827` is unsigned. The installer selects that kernel through `GRUB_TOP_LEVEL`; Ubuntu's generic 7.0 kernel remains installed as a fallback.

Camera and X91L LTE support are new in this release and require physical acceptance testing. See <<known-limitations>>.

== What the project installs

The autoinstall selects the minimized `ubuntu-desktop-minimal` source and configures:

* locale `en_US.UTF-8`, Italian keyboard layout, and timezone `Europe/Rome`;
* no installer refresh, GeoIP lookup, online driver search, or driver installation;
* no configured Ethernet interfaces and APT's `offline-install` fallback;
* a direct whole-disk layout on the dynamically discovered `CJNB4R` eMMC in production;
* the 15 selected Yoga Book packages plus their offline Ubuntu dependency closure;
* `7.2.0-yogabook-20260828-163827` as GRUB's top-level kernel;
* a production-only graphical health check, persistent boot diagnostics, and one-shot generic-kernel fallback;
* an automatic poweroff after installation.

== Build-host requirements

Use an Ubuntu amd64 host with:

* https://taskfile.dev[Task] 3.x;
* Docker with permission to run `ubuntu:26.04` containers;
* Internet access while downloading the source ISO, release packages, container image, and dependency closure;
* at least 30 GiB of free space for one clean build, plus additional space for Docker layers, VM disks, and logs.

Installation is offline; the build is not. `deb:resolve` intentionally uses the Ubuntu repositories while assembling the closure, then proves that the selected packages install in a second container started with `--network none`.

Install host utilities with:

[source,shell]
----
task setup
----

This installs download, ISO, GRUB, squashfs, cloud-init, JSON-schema, password, and QEMU utilities. It does not install Task or Docker; use the https://docs.docker.com/engine/install/ubuntu/[official Docker Engine instructions] when Docker is not already configured.

For physical installation, also provide:

* an 8 GB or larger USB drive;
* a powered USB/OTG hub;
* external power for the Yoga Book;
* a verified backup of the internal eMMC.

== Configuration

No `.env` file is required for the default Ubuntu 26.04 build. Task loads `.env` when it exists; start from `.example.env` only when overriding the source image:

[source,shell]
----
cp .example.env .env
----

[cols="2,3,2",options="header"]
|===
| Variable | Meaning | Default
| `ISO_URL` | Source Ubuntu Desktop ISO URL. The basename determines the downloaded filename. | Ubuntu 26.04 Desktop amd64 release URL
| `ISO_FILE` | Local source ISO consumed by extract, remaster, verify, and VM tasks. Keep it consistent with `ISO_URL`. | `DATA/ISO/official/ubuntu-26.04-desktop-amd64.iso`
| `ISO_SHA256` | Expected source-ISO digest. If unset, `iso:download` reads `SHA256SUMS` beside `ISO_URL`. | unset in Task; pinned in `.example.env`
| `ISO_FORCE_VERIFY` | Set to `1` to bypass the verified-file metadata cache and hash the source ISO again. | `0`
|===

`AUTOINSTALL_TEST_MODE`, `AUTOINSTALL_TARGET_DISK`, `VM_TEST_DISPLAY`, and `VM_TEST_NAME` are internal test controls set by the supplied tasks. Do not put them in `.env` for production builds.

== Quick start: production candidate

[source,shell]
----
task setup
task build
----

`task build` runs a clean pipeline:

. remove generated extraction, remaster, render, and package work files;
. download and SHA256-check the Ubuntu ISO;
. download and verify all 15 pinned Yoga Book release assets;
. select 15 package identities and resolve a clean dependency closure;
. install the closure in a network-disabled Ubuntu 26.04 container;
. extract the source ISO;
. render and validate production NoCloud data;
. patch GRUB, NoCloud data, packages, indexes, and checksums;
. remaster using the source image's hybrid boot layout and the `Ubuntu-26.04-Yoga-Book` volume label;
. verify the volume label, BIOS, UEFI, GPT, embedded content, manifests, and output SHA256.

Default-build output:

[source,text]
----
DATA/ISO/remastered/ubuntu-26.04-desktop-amd64-autoinstall.iso
DATA/ISO/remastered/ubuntu-26.04-desktop-amd64-autoinstall.iso.sha256
----

The ISO filesystem volume label is `Ubuntu-26.04-Yoga-Book`; desktop environments use this as the USB display name after the image is written.

Verify the sidecar before copying the image:

[source,shell]
----
cd DATA/ISO/remastered
sha256sum --check ubuntu-26.04-desktop-amd64-autoinstall.iso.sha256
----

To write the existing verified production image to a USB disk without rebuilding it, run:

[source,shell]
----
task iso:burn:usb
----

This revalidates the ISO checksum and embedded production guard before offering any device. If source files changed, or the production ISO does not exist, clean-build and burn in one command instead:

[source,shell]
----
task iso:build:burn:usb
----

The burn workflow lists whole, writable USB-transport disks large enough for the ISO. Desktop-auto-mounted filesystems under `/run/media/$USER/` or `/media/$USER/` remain selectable and are shown before confirmation. After the exact phrase `ERASE /dev/<device>`, the task rechecks the device identity, automatically unmounts those desktop filesystems, proves that no mount remains, writes the hybrid image with `dd`, flushes it, and SHA256-verifies the ISO-length bytes read back from the USB. Mounts outside the desktop media directories remain excluded; there is no non-interactive or skip-verification mode.

NOTE: `task build` starts by deleting generated remastered images. Running it after `task build-vm-test` removes the test ISO; running `task build-vm-test` after it removes the production ISO. Copy any artifact you need to retain outside `DATA/ISO/remastered/`.

== VM acceptance tests

=== Build the test-only image

[source,shell]
----
task build-vm-test
----

This runs the same clean build but renders `/dev/vda`, writes `guard-mode=test`, and names the result:

[source,text]
----
DATA/ISO/remastered/ubuntu-26.04-desktop-amd64-test-autoinstall.iso
DATA/ISO/remastered/ubuntu-26.04-desktop-amd64-test-autoinstall.iso.sha256
----

WARNING: Never write a `*-test-autoinstall.iso` to physical installation media. Test mode deliberately bypasses the DMI, eMMC-model, and Secure Boot checks so QEMU can exercise the installer.

=== Headless test

[source,shell]
----
task vm-test
----

The task:

* replaces the previous headless test disk and logs;
* creates a sparse 64 GiB qcow2 disk;
* uses KVM when `/dev/kvm` is available and writable, otherwise TCG;
* gives QEMU 4 GiB RAM and two virtual CPUs;
* installs with `-nic none` and a 90-minute timeout;
* exposes the test-only installer boot on `ttyS0` so early failures are recorded;
* boots the installed disk without the ISO and uses a 15-minute timeout;
* powers off only after the installed-system verifier succeeds.

Follow the serial logs from another terminal:

[source,shell]
----
tail -f DATA/VM/install-serial.log
tail -f DATA/VM/boot-serial.log
----

The required marker is:

[source,text]
----
YOGABOOK_VM_TEST_PASS kernel=7.2.0-yogabook-20260828-163827
----

It is emitted only after checking the running Yoga Book kernel, the installed `ubuntu-desktop-minimal` profile, absence of the full `ubuntu-desktop` profile, `dpkg --audit`, offline `apt-get check`, all 15 selected packages, and `GRUB_TOP_LEVEL`. QEMU's default firmware exercises the BIOS boot path; `iso:verify` separately verifies that the ISO also retains a UEFI boot entry and GPT metadata.

=== Graphical test

[source,shell]
----
task vm-test-gui
----

This performs the same unattended NIC-less acceptance test with GTK output. Do not interact with or close the QEMU window. The installation window closes at poweroff and a second window opens for installed-system verification.

Graphical artifacts are isolated from the headless run:

[source,text]
----
DATA/VM/yogabook-test-gui.qcow2
DATA/VM/yogabook-test-gui-install-serial.log
DATA/VM/yogabook-test-gui-boot-serial.log
----

Do not run headless and graphical tests concurrently unless the host has enough CPU, RAM, and storage bandwidth.

== Physical installation

. Insert the USB drive in the build host. Normal desktop automounting is supported.
. Run `task iso:burn:usb` to reuse the existing verified production ISO, or `task iso:build:burn:usb` when its sources changed. The workflow verifies the ISO and its production guard, automatically unmounts the selected USB's desktop-mounted filesystems after confirmation, and writes and read-back-verifies the disk. Do not use the VM-test ISO.
. Back up the entire eMMC and prove that the backup is readable.
. Disable Secure Boot in the Yoga Book firmware settings.
. Connect the USB drive and external power through a powered OTG hub.
. Boot the Yoga Book from USB. `Ubuntu Autoinstall` is selected automatically after a one-second GRUB countdown; press an arrow key immediately to use a diagnostic entry.
. Leave the installation unattended. A hardware mismatch aborts before storage configuration; success powers the machine off.
. Remove the USB drive and boot from internal eMMC.
. Allow up to three minutes for the first graphical boot. If the custom kernel never exposes a healthy DSI/GDM session, the installed health service saves diagnostics, selects the preserved generic Ubuntu kernel, and reboots once. It never retries that fallback automatically.
. Log in as `yoga` / `yoga`, immediately run `passwd`, and complete the acceptance procedure below.

The GRUB image also retains `Try or Install Ubuntu` and `Ubuntu (safe graphics)` entries for diagnostics. Those entries are not the automated recovery workflow.

== Mandatory YB1-X91L acceptance

Preserve `/var/log/installer/` after the first internal boot. The installed system also stores the rendered user-data and embedded package manifest in `/var/log/installer/autoinstall-media/`.

Copy link:docs/hardware-test-result.adoc[`docs/hardware-test-result.adoc`] to a dated result file, for example:

[source,shell]
----
cp docs/hardware-test-result.adoc docs/hardware-test-result-2026-08-13.adoc
----

Record the device identity, ISO digest, backup evidence, installer logs, and these command results:

[source,shell]
----
test "$(cat /sys/class/dmi/id/product_name)" = "Lenovo YB1-X91L"
EMMC="$(for D in /sys/class/block/mmcblk[0-9]; do test -r "$D/device/name" || continue; test "$(tr -d '[:space:]' <"$D/device/name")" = CJNB4R && basename "$D"; done)"
test -n "$EMMC"
test -b "/dev/${EMMC}boot0"
test -b "/dev/${EMMC}boot1"
test "$(uname -r)" = 7.2.0-yogabook-20260828-163827
sudo dpkg --audit
sudo apt-get --no-download check
dpkg-query -W alsa-ucm-conf-yogabook \
  linux-headers-7.2.0-yogabook-20260828-163827 \
  linux-image-7.2.0-yogabook-20260828-163827 \
  sof-topology-yogabook halo-keyboard yogabook-sensors \
  yogabook-camera yogabook-gnss yogabook-validator \
  gnome-control-center gnome-control-center-data \
  gir1.2-mutter-18 libmutter-18-0 mutter-common mutter-common-bin
sudo systemctl status yogabook-graphical-health.service --no-pager
sudo cat /var/log/yogabook-graphical-health/boot.log
----

Manually verify touch keyboard, pen-mode switching, sound, rotation sensors, Wi-Fi, Bluetooth, front and rear camera streaming, LTE, GNSS, suspend/resume, and reboot. The result remains *NOT RECOVERY-READY* until every required field has evidence and the overall status is updated.

[[customize-the-installed-identity]]
== Customize the installed identity

Edit the tracked `identity` mapping in `nocloud/user-data`. To generate and verify a new password hash:

[source,shell]
----
task password-hash
task password-check HASH='$6$salt$hash'
----

Paste the complete hash into `identity.password`, keeping it quoted. Then run:

[source,shell]
----
task test-render-autoinstall
task build-vm-test
task vm-test
----

If the username or hostname changes, also review `nocloud/meta-data` and every acceptance instruction that refers to `yoga`. Configuration is intentionally tracked; `.env` does not inject credentials.

For package, kernel, release, or storage changes, read link:docs/architecture.adoc[`docs/architecture.adoc`] before editing. These values are coupled to manifests, late commands, verification scripts, and acceptance criteria.

== Troubleshooting

See link:docs/troubleshooting.adoc[`docs/troubleshooting.adoc`] for symptom-based help. Start with these checks:

[source,shell]
----
task --list-all
task test-render-autoinstall
# After deb:resolve:
task deb:verify
# After a production build:
task iso:verify
# After build-vm-test instead:
AUTOINSTALL_TEST_MODE=1 task iso:verify
----

When a VM test is running, inspect the serial log rather than assuming a quiet terminal means it has stalled. Never start a second test against the same headless artifact set.

== Project internals

link:docs/architecture.adoc[`docs/architecture.adoc`] describes the trust boundaries, source tree, build stages, manifests, safety invariants, and update procedure. The short version is:

* tracked manifests define immutable upstream inputs and selected package identities;
* `nocloud/user-data` defines the production install;
* test rendering changes only the target disk and guard mode;
* build-time verification proves the exact ISO contents;
* VM testing proves unattended offline installation and first boot;
* only physical testing can prove Yoga Book hardware behavior.

[[known-limitations]]
== Known limitations

* Camera support uses the staging AtomISP driver. The packaged cameras passed direct tablet streaming tests, but a newly installed ISO still requires physical acceptance.
* LTE and GNSS passed on the current tablet installation; they remain unproven for this installer image until the physical acceptance record passes.
* The Yoga Book kernel is unsigned, so Secure Boot must be disabled.
* VM acceptance cannot validate touch, pen mode, sound, sensors, radio hardware, suspend/resume, or the physical eMMC guard.
* The standard VM workflow exercises BIOS boot; UEFI presence is checked structurally by `iso:verify`.
* Ubuntu repository contents can change after a build. The generated package manifest and ISO checksum identify exactly what a particular build contained.

Do not describe an image as recovery-ready without a completed hardware record and preserved installer logs.
