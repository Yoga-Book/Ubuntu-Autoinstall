= Ubuntu 26.04 Offline Autoinstall for Lenovo Yoga Book YB1-X91L
:source-highlighter: rouge

== Scope and safety

This project builds a hybrid BIOS/UEFI Ubuntu 26.04 Desktop autoinstall ISO for the *Lenovo Yoga Book YB1-X91L*. It bundles the upstream Yoga Book kernel and support packages plus their Ubuntu dependency closure, so installation does not require a NIC.

WARNING: The production image unconditionally erases the complete `/dev/mmcblk0` eMMC after its safety checks pass. Back up every required file before booting it. There is no in-place upgrade or preservation mode.

The production installer aborts before storage is configured unless all of these conditions are true:

* DMI product name is exactly `Lenovo YB1-X91L`.
* `/dev/mmcblk0` exists and is non-removable.
* The eMMC reports model `CWBD3R`.
* UEFI Secure Boot is disabled.

Secure Boot must remain disabled because `6.17.4-yogabook1` is unsigned. Ubuntu's generic 7.0 kernel remains installed as a GRUB fallback, while `GRUB_TOP_LEVEL` selects the Yoga Book kernel by default.

The cameras and X91L LTE modem are not supported by the upstream Yoga Book work and are not acceptance criteria.

== Requirements

Use an Ubuntu build host with Docker and https://taskfile.dev[Task]. Install the remaining tools with:

[source,shell]
----
task setup
----

`task setup` installs the ISO, squashfs, cloud-init schema, Python schema, and QEMU utilities. Docker is intentionally not installed or configured by this project.

For physical installation, also provide:

* an 8 GB or larger USB drive;
* a powered USB/OTG hub (the Yoga Book's port cannot reliably power all installation devices);
* a verified backup of the internal eMMC.

== Default credentials

The installed system uses these documented default credentials:

[cols="1,1",options="header"]
|===
| Username | Password
| `yoga` | `yoga`
|===

WARNING: These credentials are public. Change the password immediately after the first boot with `passwd`.

The matching SHA-512 password hash is committed in `nocloud/user-data`, which is the authoritative autoinstall configuration. `AUTOINSTALL_PASSWORD_HASH` is not read from `.env`, so local build settings cannot silently change the documented login.

== One-command clean offline build

[source,shell]
----
task build
----

The task performs, in order:

. clean generated package, extraction, render, and remaster directories;
. download and SHA256-check the Ubuntu 26.04 ISO;
. download and check all six pinned `debs-20251026` assets;
. select five distinct package names (`yogabook-support` `1.5.ubuntu1` supersedes `1.5`);
. resolve the Ubuntu 26.04 dependency closure from a clean directory;
. install that closure in a Docker container with `--network none`;
. extract the official ISO and render the tracked autoinstall data;
. validate user-data with cloud-init and the exact Subiquity schema embedded in that ISO;
. embed the packages and their complete identity/SHA256 manifest;
. remaster and verify hybrid BIOS/UEFI/GPT metadata, exact files, full-desktop selection, package hashes, and absence of stale NoCloud/package files;
. write `DATA/ISO/remastered/ubuntu-26.04-desktop-amd64-autoinstall.iso.sha256`.

The six immutable upstream names and hashes are tracked in `manifests/yogabook-release-debs.sha256`. The five selected identities are tracked separately in `manifests/yogabook-selected-packages.tsv`.

The rendered installer explicitly selects `ubuntu-desktop`, disables installer refresh, GeoIP, driver search and driver installation, supplies no DHCP interfaces, and uses APT's documented `offline-install` fallback. It sets `Europe/Rome` and powers off when installation completes.

Individual stages remain available as `task iso:download`, `task deb:download`, `task deb:resolve`, `task iso:extract`, `task iso:patch`, and `task iso:remaster`.

== NIC-less VM acceptance test

The VM image is deliberately named `*-test-autoinstall.iso`, targets `/dev/vda`, and bypasses the physical DMI/eMMC/Secure Boot guard. Never write it to installation media.

[source,shell]
----
task build-vm-test
task vm-test
----

`task vm-test` creates a disposable 64 GiB qcow2 disk, starts QEMU with `-nic none`, waits for the unattended installer to power off, removes the ISO from the second boot, and waits for an installed-system check to report:

[source,text]
----
YOGABOOK_VM_TEST_PASS kernel=6.17.4-yogabook1
----

That marker is emitted only after checking the running kernel, `dpkg --audit`, offline `apt-get check`, the five selected packages, and the GRUB top-level setting. Logs and the disposable disk remain under ignored `DATA/VM/` for inspection.

For the same unattended acceptance test with a visible GTK console, run:

[source,shell]
----
task vm-test-gui
----

The installer window closes at the automatic poweroff, then a second window opens while the installed system is verified. Do not close either window or interact with the automated installation. The graphical test uses its own `DATA/VM/yogabook-test-gui.qcow2` disk and `yogabook-test-gui-*-serial.log` files, so it does not overwrite headless-test artifacts. It still uses `-nic none`; graphics do not weaken the offline test.

== Physical installation procedure

. Verify the ISO sidecar with `(cd DATA/ISO/remastered && sha256sum --check ubuntu-26.04-desktop-amd64-autoinstall.iso.sha256)`.
. Back up the complete eMMC and prove the backup can be read.
. Disable Secure Boot in the Yoga Book UEFI settings.
. Write the production ISO to the USB drive using a raw-image tool. Triple-check the USB device path before writing; this repository intentionally does not automate destructive USB writes.
. Connect external power and the USB drive through a powered OTG hub.
. Boot the Yoga Book from USB and leave it unattended. A safety mismatch aborts before partitioning. A successful install powers the machine off.
. Remove the USB drive, then boot from the internal eMMC.

Do not call an image recovery-ready until this exact physical test has passed.

== Mandatory YB1-X91L acceptance record

After the first internal boot, preserve `/var/log/installer/`. The installed system also contains the exact rendered user-data and package manifest under `/var/log/installer/autoinstall-media/`.

Record the date, ISO SHA256, device identity, tester, and results in a copy of `docs/hardware-test-result.adoc`. The pass requires:

[source,shell]
----
test "$(uname -r)" = 6.17.4-yogabook1
sudo dpkg --audit
sudo apt-get --no-download check
dpkg-query -W alsa-ucm-conf-yogabook \
  linux-headers-6.17.4-yogabook1 \
  linux-image-6.17.4-yogabook1 \
  touch-keyboard yogabook-support
----

Also verify the touch keyboard, pen-mode switching, sound, rotation sensors, Wi-Fi, Bluetooth, suspend/resume, and reboot. Cameras and LTE should be recorded as upstream limitations rather than failures.

Until a completed hardware record and installer logs are archived, the output is a *candidate image*, not a recovery-ready image.
